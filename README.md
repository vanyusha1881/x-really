# x-really · 推文谣言检查器

在 X（Twitter）上一键检查推文是否为谣言的浏览器插件。基于 AI 多模态分析（文本 + 配图 + 联网核查），给出 **判定 / 结论 / 依据 / 来源**。

> 名称含义：**X-Really** —— "X 上发的，到底是不是真的？"（Is it **really** true?）

## ✨ 功能特性

- 🛡 **操作栏一键检查**：每条推文操作栏（回复/转发/点赞一排）末尾自动出现检查按钮，点击即分析，完成后按钮按判定结果着色
- 📋 **手动文本检查**：点击工具栏图标，粘贴任意文本也能分析
- 🎯 **明确三档判定**：谣言 / 不是谣言 / 存疑（存疑仅在确实无法判断时使用，不允许用"存疑"回避结论）
- 🔍 **联网核查**：核查前自动检索 **Google → Bing → DuckDuckGo → 百度**（Google 优先，国际信源覆盖更全），结合 AI 给出权威结论，卡片标注引用来源与实际命中的检索源
- 🧠 **多角度检索**：从推文提取关键实体（公司/头衔/人名/事件）→ 派生 2-3 个查询（原文 / 去年份前缀 / 实体组合）→ 汇总去重，**避免单一查询被无关结果淹没**
- 🖼 **推文配图全量多模态分析**：自动抓取推文全部配图（最多 4 张）+ **引用推文的文本**一并转多模态输入，AI 核查图文是否相符、是否断章取义 / 伪造 / 移花接木
- 📋 **内容回执**：结果卡片明确标注「已分析：正文 N 字 · 引用推文 M 字 · 配图 X/Y 张」，让你一眼确认模型实际读到了什么，杜绝静默丢内容
- 👁 **多模态能力提示（可选，不强制）**：静态识别 + 1×1 图片实测判断模型是否支持图片输入，结果按模型缓存；不支持图片的模型**同样可以绑定**，会自动降级为纯文字分析（判定准确性主要取决于模型推理能力，与是否支持图片无关）
- 💡 **简洁输出**：一句话明确结论 + 最多 3 条短依据，无冗余说明
- 🧠 **兼容任意 OpenAI 协议**：内置 DeepSeek / 智谱 GLM / Moonshot(Kimi) / 通义千问 / 硅基流动 / OpenRouter / Ollama 等预设
- 📥 **模型列表拉取**：一键从 `/models` 接口拉取可用模型，带搜索下拉与 24h 本地缓存（参考 cc-switch）
- 👁 **多模态能力检测**：静态命名识别 + 1×1 图片实测双重判断模型是否支持图片输入，结果按模型缓存
- 🕘 **最近 20 条历史**：自动保存，Popup 内可回看
- 🌗 **明暗双主题兼容**：注入卡片为深色面板，适配 X 的暗/亮主题
- 🔒 **本地优先**：API Key 仅存于浏览器 `chrome.storage.sync`，不上传任何第三方

## 📦 安装

> 本项目使用 Chrome Manifest V3（兼容 Edge、Arc、Brave 等 Chromium 浏览器）

1. 下载或克隆本仓库
   ```bash
   git clone https://github.com/vanyusha1881/x-really.git
   ```
2. 打开浏览器，访问 `chrome://extensions/`
3. 打开右上角「**开发者模式**」
4. 点击「**加载已解压的扩展程序**」，选择本仓库根目录（含 `manifest.json` 的那一层）
5. 安装完成后，右键工具栏图标 → **固定**到工具栏，方便使用

## ⚙️ 配置 API

点击工具栏图标 → 右上角齿轮按钮，进入设置页。

### 1. 选择服务商预设

设置页顶部提供预设卡片，**点击即自动填充**接口地址与推荐模型：

| 预设 | Base URL | 推荐模型 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.5-flash` |
| Moonshot · Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-turbo` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai/gpt-4o-mini` |
| Ollama 本地 | `http://localhost:11434/v1` | 本机已拉取的模型（无需 Key） |
| 自定义 | 任意 OpenAI 兼容地址 | 手动填写 |

每个预设卡片附带「获取 API Key」直达链接；切换预设不会清除已填写的 Key。

### 2. 填写 API Key 并选择模型

- **模型拉取**：点击「拉取模型列表」，通过 OpenAI 兼容 `/models` 接口获取该服务商全部可用模型，支持搜索过滤；结果缓存 24 小时。拉取失败（部分服务商不支持该接口）时可直接输入，或点击「常用模型」快捷填充。
- **多模态能力提示**：模型名变化时即时显示静态识别结果（✅ 支持多模态 / 🚫 不支持图片 / ❓ 未知）；点击「实测检测」会发送一张 1×1 测试图片做真实验证，结果按模型缓存。
- **多模态不是必需项**：保存配置**不会**因模型不支持图片而拦截。判定准确性主要取决于模型的推理能力，纯文本模型（如 `deepseek-chat`、`deepseek-reasoner`）通常比弱视觉模型判断更准。不支持图片时，图文推文会自动只分析文字部分。

### 3. 测试连接

填写后点击「**测试连接**」，看到 ✅ 表示配置成功。

## 🚀 使用

### 方式一：在 X 上检查推文

打开 [x.com](https://x.com)，每条推文操作栏（回复/转发/点赞一排）末尾会出现 🛡 检查按钮：

1. 点击按钮 → 图标变为旋转加载态（先联网检索资料，再交由 AI 分析）
2. 几秒后，推文正文下方弹出深色结果卡片：
   - **判定标签**（🚫 谣言 / ✅ 不是谣言 / ⚠️ 存疑）
   - **一句话明确结论**
   - **依据列表**（最多 3 条，注明来自"搜索资料"还是"知识分析"）
   - **🔍 来源**：引用的搜索资料域名
   - **🖼 配图说明**：显示"已结合 N 张配图分析"；若模型不支持图片会标注"配图未分析"
3. 检查完成后，操作栏按钮会**按判定结果着色**，悬停可查看结论
4. 点击卡片右上角 `×` 可关闭

> 推文文本变化（点赞、转发后重排）会自动重置按钮与结果。

### 方式二：手动检查任意文本

点击工具栏的 X-Really 图标：

- 顶部状态栏：显示当前配置与是否就绪
- 文本框：粘贴任意推文 / 新闻 / 聊天记录
- 点击「开始检查」（或 `Ctrl+Enter`）
- 下方显示历史检测列表，可一键清空

## 🧠 工作原理

```
┌──────────────┐    chrome.runtime     ┌─────────────────────┐
│ Content 脚本  │  ── sendMessage ──>   │ Background Service  │
│ (操作栏按钮)  │                       │   Worker            │
└──────────────┘                       └──────────┬──────────┘
                                                  │ ① 联网检索
                                                  ▼
                                       ┌─────────────────────┐
                                       │ Google / Bing / DDG │
                                       │ / 百度（多角度汇总）   │
                                       └──────────┬──────────┘
                                                  │ ② 推文 + 资料
                                                  │    + 配图(base64)
                                                  ▼
                                       ┌─────────────────────┐
                                       │ OpenAI 兼容 API      │
                                       │ (Chat Completions)   │
                                       └──────────┬──────────┘
                                                  │
                                        JSON: {verdict, summary,
                                        reasons, sources}
                                                  │
┌──────────────┐                       ┌──────────▼──────────┐
│ Content 脚本  │  <── sendResponse ── │ 后台解析 + 历史记录  │
│ 渲染判定卡片  │                       │                     │
└──────────────┘                       └─────────────────────┘
```

- **联网核查**：核查前自动从推文提取实体（公司/头衔/人名/事件），派生 2-3 个查询角度（原文 / 去年份前缀 / 实体组合），**Google → Bing → DDG → 百度** 多引擎兜底；某个引擎失败会记入 30 分钟冷却名单，避免每次核查白等超时
- **配图多模态分析**（模型支持时）：Content 脚本抓取推文全部配图 URL（`pbs.twimg.com/media`，最多 4 张）+ 引用推文文本，后台下载转 base64 后以 `image_url` 形式随文本一并发送；若模型报图片不支持错误，自动降级为纯文本重试并在卡片标注
- **绑定门禁**：保存时按"静态识别 → 缓存结果 → 1×1 图片实测"三重校验模型视觉能力，不支持的模型拒绝绑定并缓存结果，避免重复探测
- **判定 prompt**：明确"严禁用存疑回避判断"，依据可靠信源给出明确结论；严格输出 JSON（容错解析，自动剥离 ```json 围栏）
- **谣言复核关**：联网检索失败时若初判为"谣言"，自动发起第二次复核——模型必须给出**确切可查证的矛盾事实**才能维持谣言判定，给不出则强制降级为"存疑"，杜绝"没听说过/无媒体报道/情节离奇"式误判
- **判定档位**：
  - `rumor` 谣言 —— 明显虚假、已被证伪
  - `not_rumor` 不是谣言 —— 与可靠信源相符
  - `suspected` 存疑 —— 仅在确实无法判断时使用（搜索无结果且超出知识范围）
- **历史记录**：最近 20 条检查结果，仅存于 `chrome.storage.local`（不跨设备同步）
- **文本长度**：单次检查截断 4000 字符

## 🌐 关于网络访问（Google 能不能用？）

**取决于 Chrome 的代理配置，而不是插件本身。** 插件的联网请求走的是 Chrome 的网络栈，因此：

| 你的上网方式 | 插件能否访问 Google |
| --- | --- |
| 系统代理（Clash「系统代理」开启、PAC 脚本等） | ✅ 能 |
| VPN TUN / 全局模式（Clash TUN、WireGuard、全局路由） | ✅ 能 |
| 仅浏览器内走代理扩展（SwitchyOmega 等） | ✅ 能（Chrome 自身代理生效即可） |
| Chrome 独立设置了代理（`chrome://settings/system`） | ✅ 能 |
| 改 hosts / 智能 DNS 直连 | ✅ 能 |

**判断方法：在 Chrome 里直接打开 `google.com`，能开，插件就能用。**

- 插件已申请 `https://*/*` 权限，可访问任意站点，不受同源限制
- 若代理需要认证，由 Chrome 按系统凭据处理，插件无需额外配置
- Google 不可达时会自动降级到 Bing → DDG → 百度，不影响使用；结果卡片底部的回执会显示本次实际命中的检索源（如 `🔎 Google`），方便确认

## 🔒 隐私

- ✅ API Key 与所有配置仅保存在浏览器本地（`chrome.storage.sync`）
- ✅ 历史记录仅保存在浏览器本地（`chrome.storage.local`）
- ✅ 网络请求仅发生在「用户主动点击检查」时：搜索发往 Bing / DuckDuckGo，分析发往用户自己配置的 API 接口
- ❌ 不收集任何分析、统计、用户行为数据
